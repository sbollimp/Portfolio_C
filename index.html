Featured project

Clinical Document NLP Pipeline

Unstructured clinical notes → analytics-ready fields, with an explanation on every prediction

A discharge summary is a wall of prose; an analytics team needs rows. This is the full path between the two — ingestion, de-identification, sectionisation, hybrid NER, assertion detection, concept normalisation, document classification and structuring. Three recognisers with complementary failure modes (a statistical BIO tagger, a longest-match gazetteer and regex rules) merge precision-first, so a known drug name is never lost to model hesitation.

Assertion detection decides what actually counts: denies pneumonia, mother had pneumonia and monitor for pneumonia are four different facts, tracked per mention rather than per concept. Every prediction carries exact feature attribution — the arithmetic the linear model actually performed, not a surrogate fit. That report caught a real shortcut: attending-physician names ranked among the top features for readmission risk, so the model was partly learning who wrote the note.

Fraud & Anomaly Detection

An evaluation-first approach to extreme class imbalance

Detecting rare events at a 0.2% fraud rate — and, more importantly, evaluating that detection honestly. Six detectors (gradient boosting, logistic regression, isolation forest, PCA reconstruction and two deliberate baselines) sit behind one common scoring interface so supervised and unsupervised approaches compare on identical terms.

The project shows why accuracy is actively misleading here: an always-“normal” baseline scores 99.78%, above several working detectors. Thresholds are chosen on validation under a cost model rather than left at 0.5, and 56 tests enforce chronological splits, scaler-fit integrity and label-leakage guarantees.

Featured project

E-commerce Recommendation Engine

Five models, one offline harness, and an A/B test that reads out honestly

A production-shaped product recommender: collaborative filtering and content-based models blended into a hybrid, an offline evaluation harness that benchmarks all five on the same temporal split, and a FastAPI scoring service that assigns traffic to A/B variants and logs every impression so online lift can actually be measured. ALS is ~60 lines of NumPy rather than a compiled package, so it installs anywhere. 388k events, 6,000 customers, 1,500 products, 98.1% sparse.

Two decisions carry the project. Ranking metrics are reported alongside coverage, novelty, diversity and a Gini index on exposure — a model that shows everyone the same 20 best-sellers scores respectably on NDCG and is useless as a merchandising surface. And the A/B analysis clusters variance by customer via the delta method, because impressions from one customer aren’t independent; the naive binomial test would have reported p = 0.0005 for CTR, an order of magnitude more confident than the data supports.

Demand Forecasting Benchmark

Rolling-origin evaluation across statistical, gradient-boosted and neural back-ends

Benchmarks every model on the same protocol — five rolling origins, a 28-day horizon, one daily demand panel — with statsmodels, LightGBM, XGBoost and PyTorch back-ends behind a single interface. The minimal install runs the whole benchmark without any of them, so the comparison never depends on what happens to be on the machine.

The panel is generated from a seed rather than downloaded, so a fresh clone reproduces byte-identical numbers. Validation rejects duplicate (unique_id, ds) rows, negative demand and calendar gaps before anything is fitted — a silent gap turns every lag feature into a subtly wrong number. The schema maps onto M5, Rossmann, Favorita and Online Retail II with light renaming.

MLOps Experiment Platform

Notebook experiment → tracked, versioned, containerised, deployable artifact

A reusable template for the path production ML actually needs: MLflow experiment tracking and Model Registry versioning, SHA-256 dataset fingerprinting, model signature and input-example logging, and a generated model card on every run.

Promotion is a quality gate, not a manual step — a registered version moves from candidate to champion only if its F1 clears a configured threshold, and the FastAPI service loads models:/name@champion so a deployment advances by moving an alias rather than changing code. Separate Docker images for training and serving; GitHub Actions runs tests, trains against an ephemeral MLflow server, then builds both and pushes to GHCR on a version tag.
